# Contract Breaker -- Android app (Capacitor)

`web-build/` (the exact same HTML/CSS/JS game, unchanged) is wrapped into an
installable Android app with [Capacitor](https://capacitorjs.com/). No game
logic or UI was rewritten -- Capacitor just loads `web-build/` inside a
native WebView shell.

- **Package name:** `com.futurepath.contractbreaker`
- **Orientation:** locked to landscape (`sensorLandscape` -- allows either
  landscape rotation, never portrait) via `android:screenOrientation` on
  `MainActivity` in `android/app/src/main/AndroidManifest.xml`.
- **Web assets source:** `web-build/` (set as `webDir` in
  `capacitor.config.json`).

## What's committed vs. generated

- `capacitor.config.json` and `android/` (the native project scaffold,
  manifest, Gradle files) are committed.
- `android/app/src/main/assets/public/` (the copied web assets),
  `android/local.properties`, `android/**/build/`, `android/**/.gradle/`,
  and any `*.apk` are **not** committed -- they're generated by the build
  and are machine/output-specific (standard for Android projects; see
  `android/.gitignore`).

## Building the debug APK

### Prerequisites

- Node.js (already needed for the rest of this project)
- JDK 17+
- Android SDK (platform-tools, an `android-34`+ platform, matching
  build-tools) -- easiest via **Android Studio**, which manages all of this
  for you.

### Option A -- Android Studio (simplest)

1. `npm install`
2. `npx cap sync android` (copies `web-build/` into the native project)
3. Open the `android/` folder in Android Studio.
4. Let it finish Gradle sync, then **Build > Build Bundle(s) / APK(s) >
   Build APK(s)**, or press Run to install straight onto a connected
   device/emulator.
5. The APK lands at `android/app/build/outputs/apk/debug/app-debug.apk`.

### Option B -- command line

```
npm install
npm run android:build
```

This runs `cap sync android` then `./gradlew assembleDebug`. Output:
`android/app/build/outputs/apk/debug/app-debug.apk`.

If you edit anything under `web-build/` (or re-run `npm run build:web`
after changing the engine in `src/`), re-run `npx cap sync android` (or
`npm run android:build`, which does it for you) before rebuilding so the
native project picks up the changes.

## Signing

This is a **debug build**, signed automatically with the standard Android
debug keystore (auto-generated the first time you build; `CN=Android
Debug`). That's exactly what's needed to sideload for testing -- it is not
a Play Store release signature, and none was set up (per the brief: no Play
Store signing needed yet).

## Installing on your phone (sideloading)

1. On your phone: **Settings > Security** (or **Apps**) > enable **Install
   unknown apps** for whichever app you'll use to open the APK (Files,
   Chrome, etc.), or for `adb` specifically you don't need this toggle.
2. Get `app-debug.apk` onto the phone, then either:
   - **Tap the file** in your file manager / downloads and confirm the
     install prompt, or
   - **Via USB with `adb`:** enable Developer Options > USB debugging on
     the phone, connect it, then from this project:
     ```
     adb install -r android/app/build/outputs/apk/debug/app-debug.apk
     ```
3. Launch "Contract Breaker" from the app drawer. It should open directly
   in landscape and stay there.

## Touch input

The web build only ever used `click` listeners (no hover-only or
mouse-only interactions), so tapping cards/nodes/buttons in the wrapped app
works the same as clicking in a browser. On top of that, `web-build/index.html`
adds a few touch-specific CSS rules for the native shell:

- `touch-action: manipulation` (removes the double-tap-to-zoom delay)
- `-webkit-user-select: none` / `-webkit-touch-callout: none` on
  interactive elements (no long-press text-selection popup interrupting
  taps)
- `overscroll-behavior: none` (no Android overscroll glow/bounce fighting
  the map's scroll view)

These are additive CSS only -- no event-handling logic changed.

## What was verified in this environment

This sandbox has no `/dev/kvm`, so a full Android emulator wasn't usable
here (software-only x86 emulation is impractically slow without hardware
acceleration). What *was* verified directly:

- The debug APK builds successfully end-to-end with Gradle.
- `aapt dump badging` / `dump xmltree` confirm: package
  `com.futurepath.contractbreaker`, launchable activity
  `com.futurepath.contractbreaker.MainActivity`, and
  `android:screenOrientation` compiled to value `6`
  (`SCREEN_ORIENTATION_SENSOR_LANDSCAPE`) on that activity.
- `apksigner verify` confirms a valid debug signature.
- `zipalign -c -v 4` confirms the APK is correctly aligned (installable).
- The APK's `assets/public/` contains the full, unmodified `web-build/`
  output -- `index.html`, `app.js`, `engine.bundle.js`, and every card/
  enemy/boss/background art file.
- The underlying `web-build/` game itself (identical code) was already
  verified running a full game start-to-finish via Playwright/Chromium in
  the prior step -- Capacitor's Android WebView is the same Chromium
  rendering engine family, loading the same unmodified files.

What's **not** verified here: actually installing and tapping through the
app on a real device/emulator. Please sideload it and confirm -- if
anything looks off (layout, a tap not registering, etc.), let me know
specifics and I'll fix it.
